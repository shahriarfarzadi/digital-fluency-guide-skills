# Digital Tools and Factories Playbook

## Capability-first selection

Write the job, user, current friction, desired outcome, required capability, data boundary, integration need, operating owner, and exit condition before naming products.

## Stack map

Document layers for work, data, integration, application, infrastructure, people, and operating practice. For each tool record owner, dependency, critical workflow, cost, reliability, portability, security, and replacement effort.

## Machine coworker contract

Define task boundary, context sources, permissions, memory, output format, review point, failure response, logging, and performance measure. Keep consequential actions gated by an accountable person.

## Digital factory loop

Discover → shape a thin slice → build → test automatically → deploy safely → observe usage and quality → learn → reprioritize. Product, design, engineering, and operations share outcome ownership.

## DevOps checks

- version and configuration are reproducible;
- deployment and rollback are tested;
- telemetry distinguishes assignment, exposure, error, and outcome;
- incidents have an owner and learning review;
- changes are small enough to isolate.

## Tool pilot gate

Before scaling, show intended users, active usage, quality, time-to-value, failure cases, security review, integration cost, support owner, and a stop condition.

## Failure modes

- Tool-first procurement.
- Automation that removes human context without reducing risk.
- A dashboard without an operational owner.
- Continuous delivery without observability or rollback.
- A stack whose exit cost is unknown.
